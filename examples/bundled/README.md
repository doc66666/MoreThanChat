# 随客户端提供的可选示例

打开左侧「插件」，在最上方「插件示例库」选择「添加并启用」。关闭插件面板，聊天顶部就会出现入口。它们默认不安装，不需要模型额度，断开中心服务器也能使用本机功能。

| 示例 | 使用方式 | 数据与联网 |
| --- | --- | --- |
| 常用短语 | 添加自己的常用回复，点击填入当前输入框，保留已有文字，自己确认发送 | 短语保存在当前身份的本机存储；不会自动发送 |
| 专注计时 | 25 分钟专注、5 分钟休息或自定义 1–180 分钟；暂停、继续与重置 | 保存截止时间，关闭面板、休眠或重启后仍按实际时间计算；聊天顶部显示倒计时和完成状态 |
| 翻牌记忆 | 找齐八对相同图案，比较完成步数，随时重新洗牌 | 本局在插件运行期间保留，最佳纪录保存在本机 |
| 一起井字棋 | 本机双人轮流下；分享到好友／群后由各成员使用自己的客户端操作 | 本机、各服务器、各会话分别存档；联网用现有会话通信接口转发事件 |
| HTML 消息卡片 | 编辑文字摘要和 HTML、预览后发送到当前好友／群聊 | 正文随聊天消息传递；接收方启用示例后显示卡片，未启用则显示文字摘要 |

HTML 卡片是第五个可选示例。它注册 `message.body.html`，不是替换整个聊天窗口；已有的复制、引用、转发、撤回和回执仍由默认气泡提供。停用后显示摘要，重新启用会重绘历史消息。示例支持 HTML 排版、内联 CSS 和 data URL 位图；消息内容在无脚本的 iframe 内呈现，不把收到的 HTML 当插件代码执行。交互逻辑由安装的渲染插件实现，可使用现有会话通信接口。新格式发送需要中心服务器 `/v1/ping` 声明 `message-content-v1`；旧服务器会提示更新并保留待重试的消息，不会丢掉正文后假装发送成功。

卡片编辑器采用编辑／预览并排布局，小窗口下自动上下排列。未发送草稿由示例自己按会话、本机／分享实例存入当前身份的本机存储；关闭面板、切换会话、停用后重新启用或重启均可继续编辑。成功加入发送队列后清空草稿，下一次发送生成新 ID；发送结果不确定时保留原 ID，重新载入后重试也不会额外发一条。支持 Ctrl / ⌘ + Enter 发送。本机「写卡片」与分享实例的「群聊卡片」「好友卡片」入口分别标明来源。

## 联机使用

1. 安装「一起井字棋」，在下方已安装列表展开「分享到好友／群聊」，选择会话并申请分享。
2. 对方同意，或群管理员批准后，成员在自己的插件面板选择载入。
3. 打开对应会话，点击「好友井字棋」或「群聊井字棋」。本机游戏的入口单独标为「本机井字棋」，不和联机棋盘混用。
4. 两人加入即可对弈，其他成员可以观战。结束后点击「新一局」会释放两席；中途「退座换人」会清空棋盘，保留另一位玩家，让新成员入座。

对局规则、胜负、换人、快照与本机存档均由插件源码实现，中心服务器沿用已有消息转发接口，不增加游戏业务和插件数据托管。网络或版本变化后，由现有会话插件生命周期重新载入，用本机历史和在线成员快照衔接状态。示例适合协作娱乐，不是用于防作弊竞技的权威游戏服务器。

## 修改与热更新

每张卡片有「复制为草稿」。如果已经安装，会复制当前安装版本的代码；新草稿使用独立 ID，避免覆盖原插件。随后可以对内置 AI 说：

> 读取草稿 `<界面提示的草稿 ID>`，给这个插件增加……，保留原有功能，完成后校验草稿。

草稿、安装、停用、卸载、同 ID 热更新与会话分享完全复用普通用户插件的流程。示例库不会自动覆盖已安装版本，也不会因为重启或客户端升级重新启用停用的插件。卸载清理运行贡献；示例自己保存的本机数据会保留，方便重新安装后继续使用。

## 源码组织

- `catalog.json`：名称、用途、分类。
- `panel.mjs`：打包到每份示例里的小窗与本机存储辅助函数；使用应用内 HTML dialog，支持 Escape、焦点返回和明暗主题。
- 其余 `.mjs`：各插件实现。客户端将 `panel.mjs` 与单个入口拼成自包含 ES module，使用同一个 manifest 校验器、摘要、Cordis 运行时和安装控制器，未另设专用运行通道。
- `ui.slots` 为聊天顶部添加入口，`ctx.effect()` 清理定时器与订阅。插件仍可按公开的 `ui.surfaces` 契约改成其他布局，这些示例的位置不是插件框架的限制。
- 联机井字棋只使用 `sdk.network.send / subscribe / history`、`sdk.conversation`，不会借示例读取聊天内容或发送聊天消息。
- HTML 卡片使用 `sdk.chat.request({action:'send',conversationId,clientMessageId,text,content:{format:'html',version:1,body}})`，其中 `text` 为供未安装渲染器的客户端、会话预览、检索和引用使用的文字摘要。

`pnpm verify:examples-ui` 会构建并启动三个隔离的真实 Electron 用户目录，检查示例库安装、草稿复制、本机功能、重启、群／私聊审批载入与同步、热更新和卸载；日志及截图保存在 `.artifacts/examples-ui-*`。它不使用真实模型额度，也不会修改正常用户目录。

`pnpm verify:message-renderers` 用两个真实客户端检查 Markdown 双向渲染、HTML 编辑发送、缺少渲染器、热更新和错误回退、停用后重启、引用、群转发、撤回和离线送达。
