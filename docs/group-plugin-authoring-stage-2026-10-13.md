# AI 群插件链路补齐（2026-10-13）

## 状态与测试边界

已完成声明式群插件的作者契约、完整包审批分发、本机确认载入、通用状态规则和界面运行时。**本阶段没有调用 computer-use，没有启动/操控桌面窗口，也没有再次调用真实 DeepSeek。** 用户正在使用电脑，真实发行版三端验收等用户通知后再进行。

本阶段的井字棋是 `scripts/fixtures/group-game.mjs` 手写协议测试样本，只用于测试，不属于内置产品插件，不是 DS 产物。不能据此宣称 DS 闭环已经验收通过。之前的失败记录保留在 `ds-group-plugin-acceptance-2026-10-13.md`。

## 用户可见流程

1. 在 More AI 请求实时群插件。作者可读取新契约，通过 create/validate/diagnose 工具写入当前身份的 `host-private/plugin-drafts/<id>/revision-N.json`；不写仓库或安装目录。
2. 打开“插件”，群草稿显示“申请加入群聊”：选择当前中心服务器上的群及界面位置，确认指定草稿修订后提交。群详情也有“提交 AI 创作的群插件”入口。模型本身没有提交、审批或安装权限。
3. 管理员在联系人/群管理审批区查看申请人、完整插件包、权限、版本及 SHA-256 摘要，再批准或拒绝。
4. 审批前其他普通成员拿不到包，审批后通过现有中心目录同步完整内容。群草稿卡展示待审批、拒绝、批准、被替代状态。
5. 每位成员首次收到都处于待确认状态，可以“暂不载入”或“确认载入本机”。只有同意后才挂载界面；停用不影响其他成员。
6. 同意后，完整包和授权原子保存到当前身份用户目录 `group-plugins/`；授权绑定用户、中心服务器、群、插件及内容摘要。Main 每次发送前重新检查授权和摘要，中心再检查成员/审批/版本及状态修订。
7. 新版本批准后需要重新确认；当前 MVP **重置共享状态**，不执行任意迁移代码。界面和审批处有提示。未批准或拒绝新版不影响旧批准版。

## 执行与通信边界

- 新的 `group-state-machine` 是有界 JSON 状态机，不是内置井字棋选择器，也不执行 AI 生成的 JS/TS。
- Manifest 目标 `pc-ui`，权限及服务仅 `chat.network`。通用运行时支持文本、按钮、网格和表达式；AI 在包内编写动作 guard、顺序状态更新及胜负规则。
- `chat.network` 的同一窄接口供现有可信 UI 插件和新声明式运行时使用；新状态请求绑定 digest + expectedRevision，actor 和 members 由中心注入，不接受客户端伪造身份。
- 支持比较/逻辑/条件/算术、数组索引与有限 some/every/filter 等操作，无任意 URL、文件、shell、DOM 或动态代码执行。
- 源定义最多 24000 字符；24 个状态字段、16 个动作、每动作 32 次更新、64 项数组、8000 字符状态；单动作/单次界面计算预算 10000 步。解析限制表达式深度与节点数，拒绝原型路径和未知字段/操作。
- 状态在中心事务中原子提交；校验失败不产生半写入，重连和服务器重启从已保存状态恢复。聊天消息送达后清理策略不变，插件共享状态按插件生命周期保留。
- 新版本只能由原提交者追加，管理员不能误批准比当前已批准版更旧的申请。
- 新能力通过 `group-program-v1` 协商；旧客户端不接收不认识的声明式包，避免破坏其聊天目录解析。Android 尚无实现，但数据协议、状态机和 Host JSON Schema 不依赖 Electron UI。
