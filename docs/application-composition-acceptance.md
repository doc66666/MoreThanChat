## 实际客户端结果

`verify-composition-ui.mjs` 启动两份隔离 Electron 用户目录：

- 普通用户草稿安装的插件可以包装默认聊天标题，同窗口升级后只有一份有效贡献；聊天正常发送。
- 用户插件提供 `model.api` 后，默认界面使用新的服务实现。
- AI 流式回复进行中替换该服务，时间线 DOM 保持，前后两段内容完整合并，没有重复。
- 重启保留用户选择；卸载服务和视图插件后默认实现接回。
- 实际 utility Host 从用户目录载入 Node 插件，更新、卸载及回到默认 Agent 服务正常。
- 实际 Main 的中心服务可被用户插件包装；更新后消息仍能发送。
- 默认 Agent 可直接在插件面板停用、启用；停用中心连接时本机记录与组合管理仍可访问，启用后自动重连。
- 关闭插件管理不会将顶部栏滚出视口。

`verify-client-plugins-ui.mjs` 验证整桌面替换、版本失败回退、重启选择、停用与现有界面重开流程。`verify-shared-client-plugins.mjs` 完成三个客户端的群与私聊审批、分发、成员自主载入、实时对局、离线补投、新版载入和 AI 本机插件管理。新版通讯录“申请”页现可直接处理插件分享申请。

## 本次生命周期补查

本次沿着替换、热更新、停用、重启再启用完整检查，修正了以下实际问题：

- 新提供方启动成功但下游启动失败时，原流程不会完整回退。现在连同依赖者一起恢复；更新移除正在使用的服务也会回退。
- 依赖稍后才满足的覆盖插件现在会重绑现有消费者。多层服务包装保留实际引用的上游，同优先级的选择不会因热更新改变。
- Node 正常版本有持久版本指针，源码编辑失败后重启仍可加载上一接受版本；停用时不接受未经执行的源码更新。偏好和版本指针写入失败均有运行态回退，清理失败仍保留用户停用意图。
- Main 和 Host 在执行默认模块前读取停用偏好。Renderer 的偏好变更串行执行，避免快速操作相互覆盖。
- 群落子恰好发生在中心服务替换、转发订阅暂时解绑的间隙时，原流程会保存事件但漏掉界面通知。新增真实三端并发验收先复现了该问题；现在从已有本机传输记录补投间隙事件，重复订阅不重复投递，正常重连不误播历史。
- 真实聊天回归捕获到迟到的失焦状态：窗口已聚焦并滚到底部，界面仍压制已读。现在把焦点事件作为重新核对阅读位置的信号，由主进程在每次已读 IPC 到达时判断窗口当前是否聚焦，不再用界面内的旧焦点副本额外阻断。遮挡、历史阅读、后台窗口的已读抑制继续保留。

扩展后的 `verify-composition-ui.mjs` 额外覆盖用户界面/服务停用后重启与再次启用、Host 坏更新后的冷启动、默认 Agent/中心服务停用后重启、本机历史可用、启用后的离线补投与双向聊天。`verify-shared-client-plugins.mjs` 在真实群对局中主动暂停新中心服务的激活，让事件在订阅间隙到达后再继续，检查棋盘同步和单份视图。

## 后台插件管理补查（2026-11-08）

- 首次载入失败的 Main／Host Node 插件显示在管理面板中，提供具体错误、重新载入和停用入口。插件仍运行旧版但更新失败时明确说明旧版仍在运行。
- 停用后改好源码，启用时先检查最新文件；原版本本身不能启动也不再阻止加载修正版本。停用选择和版本信息在重启后保留。
- 同一份执行失败的源码不再在每次目录扫描时重复运行。修改源码或主动重试会重新执行，声明依赖尚未就绪的插件仍可在提供方加载后启动。
