# 消息插件优化与 v1.0.0 本机验收

本轮修正 HTML 示例重复发送相同内容时复用已成功发送 ID 的问题。发送结果不确定时保留原 ID，成功加入队列后清空草稿，下一次操作使用新 ID。未发送内容与尚未确认的发送 ID 由示例按当前身份、插件实例和会话保存在本机，热更新、切换会话和重启后可继续。旧实例的延迟完成不会清掉新实例已编辑的草稿。

编辑器改为编辑／预览并排布局，窄窗口上下排列；预览在输入短暂停顿后更新，支持 Ctrl / ⌘ + Enter 发送。本机、好友共享和群共享入口有不同文字，草稿相互隔离。示例存储由插件自己实现，没有新增中心服务器存储业务。

默认消息时间线维护定位节点与定位高亮。插件替换完整消息气泡时无需重新设置 `data-message-id`，默认引用定位、搜索和未读逻辑继续工作。修复旧式 `UiSlot` 错误边界在贡献更新后不恢复的问题：同一坏版本不会反复执行，修正版热更新后重新渲染。

## 本机验证

- 全量自动化：696 项通过，2 项按原配置跳过。新增 4 项草稿发送与恢复、时间线定位节点和旧式入口恢复测试。
- 类型检查、桌面与 Host 构建、协议 schema 一致性及补丁空白检查通过。
- 真实三端：Markdown、HTML 卡片、重复内容独立发送、按会话保留草稿、热更新、停用重启、错误版本与修正版、撤回、群转发、离线送达、最新位置已读通过。
- 共享渲染器：普通成员提交，管理员批准，第三个未安装本机版本的客户端自行载入后显示历史卡片；共享编辑器可向群发送，离开群后卸载运行贡献，再返回恢复草稿。
- 原有聊天体验回归通过，覆盖进入会话、返回最新、未读、昵称、AI 聊天读写及图片／文本附件输入、切服和重连。
- 中心服务器全流程窗口验收通过，覆盖好友、群聊、离线队列、送达／已读、引用定位、转发、撤回、语音、附件、身份恢复和多设备。
- Windows 中心服务器独立包通过内置运行时的 CLI 验证：配置、启停重启、日志、公开／私有模式和黑白名单管理。

源码窗口证据：`.artifacts/message-renderers-kYLIZG/report.json`，同目录 `04-editor-draft.png`、`05-shared-renderer.png`。其他日志为 `.artifacts/v1.0.0-tests.log`、`v1.0.0-typecheck.log`、`v1.0.0-final-focused-tests.log`、`v1.0.0-chat-experience.log`、`v1.0.0-central-ui.log` 和 `v1.0.0-package-central.log`。

旧 CI 曾在布局／引用测试之后仍停留历史位置，却直接等待新消息已读。本轮补上真实点击返回最新并检查到底后，再等待回执的步骤；没有通过直接设置已读绕过窗口行为。HTML iframe 验收同样等待文档完成加载，不以创建 iframe 节点本身代替内容已经显示。

本轮按用户后续指示将产品版本更新为 1.0.0，发布附件包含客户端安装器、便携 ZIP、Windows 和 Linux 中心服务器。发布流水线增加打包后的消息渲染与群插件窗口验收，公开发布以这些步骤通过为前提。未向正常用户目录安装测试插件，未使用外部模型额度。
